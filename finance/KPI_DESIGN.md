# KAMIの酵母 — KPI設計・データ設計書(ローンチ前版)

> 作成: finance-controller / ステータス: ドラフト(販売開始前に確定させる)
> 目的: **初月からM&AのデューデリジェンスにそのままKPI推移を提出できる**計測体制を作る。
> 定義を変更する場合は必ず本書を更新し、Git履歴に残すこと(定義の一貫性はDDで最初に確認される)。

---

## 1. KPIツリー(何を最重要で見るか)

```
企業価値(M&A時の評価)
└── 定期会員基盤の質 = MRR × 継続率の傾き
    ├── 獲得:  新規定期会員数、CPA/CAC(チャネル別)
    ├── 定着:  F2転換率、月次コホート継続率、解約率・解約理由
    ├── 収益性: 粗利率、LTV、CAC回収期間(payback)
    └── 資金:  13週資金繰り、在庫回転
```

**North Star Metric: アクティブ定期会員数**(単月売上ではない)。
買い手は「単発でいくら売れたか」ではなく「解約されにくい定期基盤がいくらあるか」で値段を付ける。

---

## 2. KPI定義(厳密版)

計算式を固定する。感覚で運用しない。

### 2.1 獲得

| KPI | 定義 | 粒度 |
|---|---|---|
| 新規顧客数 | 当月に初回決済が発生したユニーク顧客数 | 月次 × チャネル別 |
| CPA | 広告費 ÷ 新規注文数 | 月次 × チャネル別 |
| **CAC** | (広告宣伝費 + アフィリエイト/代理店成果報酬 + 販促費) ÷ 新規顧客数 | 月次 × チャネル別 |

- 初回半額の値引き分はCACに**含めない**(売上控除としてLTV側で反映)。二重計上を防ぐため。
- 広告費はプラットフォーム別(Meta/Google/アフィリ/インフルエンサー等)に必ず分けて記録する。

### 2.2 定着(最重要ブロック)

| KPI | 定義 | 粒度 |
|---|---|---|
| **F2転換率** | 初回購入者のうち、2回目決済に到達した割合 | 獲得月コホート別 |
| 継続率(n回) | 初回購入者のうち、n回目決済に到達した割合 | 獲得月コホート別 |
| 月次解約率 | 当月解約数 ÷ 月初アクティブ定期会員数 | 月次 |
| 解約理由分布 | 解約理由コード別の構成比 | 月次 |

- コホートは**獲得月**で固定する(「2026年9月に初回購入した人の6回目継続率」という読み方)。
- スキップ(1回休み)と解約は区別して記録する。スキップは解約ではない。

### 2.3 収益性

| KPI | 定義 |
|---|---|
| 平均注文単価(AOV) | 売上(値引後) ÷ 注文数 |
| **限界利益(注文粗利)** | 売上 −(製品原価 + 同梱物 + 資材 + 配送費 + 決済手数料 + 倉庫作業費) |
| **LTV(12ヶ月・粗利ベース)** | Σ(n回目の限界利益 × n回目到達率)を12ヶ月分合算 |
| LTV/CAC | 3.0以上を健全の目安とする(仮定・要検証) |
| CAC回収期間 | CAC ÷ 月あたり限界利益。何ヶ月で獲得コストを回収できるか |

- LTVは**売上ベースではなく粗利(限界利益)ベース**で統一する。買い手・投資家との会話で誤解が生じない。
- 販売開始直後は実績コホートが無いため、モニター調査の価格受容性と仮定継続率でモデルLTVを作り、実績が貯まり次第、毎月置き換える。

### 2.4 資金・在庫

| KPI | 定義 |
|---|---|
| MRR | アクティブ定期会員数 × 月額単価(値引後実収ベース) |
| 13週資金繰り | 週次の入出金予定(広告費・OEM仕入・入金サイトのズレを反映) |
| 在庫月数 | 在庫数 ÷ 直近3ヶ月平均出荷数 |

- OEM仕入は発注ロットが大きくキャッシュが先行する。仕入発注の意思決定は必ず13週表を更新してから行う。

## 3. データ設計(計測できる注文システムの要件)

カート/ECシステム選定時に、以下が取得・エクスポートできることを**選定条件**とする。

### 3.1 顧客マスタ(customers)

| フィールド | 型 | 備考 |
|---|---|---|
| customer_id | 一意ID | 全テーブルの結合キー。メールアドレスをIDにしない |
| acquired_at | 日時 | 初回決済日時 |
| channel_source / medium / campaign | 文字列 | UTMパラメータをそのまま保存。**手入力にしない** |
| first_offer | コード | 初回オファー種別(半額/通常/セット等) |

### 3.2 注文(orders)

| フィールド | 型 | 備考 |
|---|---|---|
| order_id / customer_id | ID | |
| ordered_at | 日時 | |
| sku | コード | 30日/60日/90日等の商品区分 |
| order_type | コード | 定期 / 単品 / 代理店卸 |
| sequence_n | 整数 | その顧客の何回目の決済か(継続率計算の根幹) |
| gross / discount / net | 金額 | 定価・値引・実収を分けて持つ |
| shipping_fee / payment_fee | 金額 | 限界利益計算用 |

### 3.3 定期ステータス(subscriptions)

| フィールド | 型 | 備考 |
|---|---|---|
| subscription_id / customer_id | ID | |
| started_at / status | | active / paused(スキップ) / canceled |
| canceled_at | 日時 | |
| cancel_reason_code | コード | **選択式**。下記コード表を使う |
| cancel_reason_text | 自由記述 | 任意 |

**解約理由コード表(ローンチ前に確定)**: ①効果を実感できない ②価格が高い ③飲み忘れる・習慣化しない ④在庫が余っている ⑤体に合わない ⑥他商品への乗り換え ⑦その他
→ ⑤(体に合わない)は件数を問わず月次で必ず個別レビューする(品質・PL保険・表示の観点)。

### 3.4 広告費(ad_spend)

月次 × チャネル別に金額を記録。媒体管理画面のスクリーンショット/CSVを毎月保存(DD時に突合可能にする)。

## 4. 月次締めルーチン(DD-ready運用)

毎月**第3営業日**までに以下を確定し、命名規則どおりに保存する:

1. `finance/monthly/YYYY-MM_kpi.csv` — 月次KPIスナップショット(テンプレ: `finance/templates/monthly_kpi_template.csv`)
2. `finance/monthly/YYYY-MM_cohort.csv` — 獲得月コホート × 決済回数の到達率マトリクス
3. `finance/monthly/YYYY-MM_cash13w.xlsx` — 13週資金繰り更新
4. 広告費のエビデンス(媒体CSV)を同フォルダに保存

ルール:
- 一度確定した過去月の数字は修正しない。誤りが見つかったら当月に「修正履歴」として注記する(遡及修正はDDで信頼を失う)
- 全ファイルはGit(または会社の共有ドライブ)で履歴管理する

## 5. 仮の目標値(すべて「仮定」— 実績3ヶ月で必ず見直す)

> ⚠ 以下は一般的なD2C健康食品の相場観からの**仮置き**であり、出典に基づく検証未了。market-researcher による国内D2C健食ベンチマーク調査で裏取りすること。

| KPI | 仮目標 | メモ |
|---|---|---|
| F2転換率 | 45%以上 | モニター継続意向10/10は好材料だが一般化しない |
| 6回継続率 | 30%以上 | 定期基盤の質を決める本丸 |
| 月次解約率 | 10%以下 | |
| CAC | ⚠見直し中 | モデルLTV初版の結果、8,000円ではLTV/CAC≥3が成立しない。中立シナリオの上限CACは約2,700円(`MODEL_LTV.md`参照)。オファー構造と併せて再設計する |
| LTV/CAC | 3.0以上 | |
| CAC回収期間 | 6ヶ月以内 | |
